## 2. ขอบเขตการทดสอบ (Test Scope)

### 2.1 ระบบและโมดูลที่ทำการทดสอบ (Modules Under Test)
* **ชื่อระบบ:** Iko-Share (Web Application & API)
* **เวอร์ชัน/บิลด์:** Version 1.0.0 (Build 2026.09-RC1)
* **โมดูลที่ครอบคลุมการทดสอบ:**
  1. **โมดูลระบบสมาชิกและการยืนยันตัวตน (Authentication & Authorization):** การลงทะเบียน, เข้าสู่ระบบ, รีเซ็ตรหัสผ่าน, และการจัดการบทบาท (Passenger, Driver, Admin)
  2. **โมดูลจัดการข้อมูลยานพาหนะ (Car Management):** การบันทึก/แก้ไขข้อมูลรถยนต์ ทะเบียน รุ่น และจำนวนที่นั่ง
  3. **โมดูลจัดการการเดินทางและอีเวนต์ (Trip & Event Management):** การสร้างทริปสำหรับคนขับ, การสร้างคำขอเดินทางของผู้โดยสาร, การผูกทริปเข้ากับอีเวนต์คอนเสิร์ต/งานเทศกาล
  4. **โมดูลระบบจองที่นั่งและการอนุมัติ (Booking Workflow):** การส่งคำขอจอง, การอนุมัติ/ปฏิเสธโดยคนขับ, การจัดการสมาชิกในทริป
  5. **โมดูลระบบห้องสนทนากลุ่ม (In-Trip Chat):** การส่งข้อความเรียลไทม์ระหว่างสมาชิกในตี้เดินทาง
  6. **โมดูลการประเมินและรีวิวร่วมกัน (Mutual Peer Review):** การให้คะแนนและความคิดเห็นระหว่างคนขับและผู้โดยสาร
  7. **โมดูลผู้ดูแลระบบและการรายงาน (Admin & Moderation):** การจัดการคำร้องเรียน, การตรวจสอบรายงานข้อความแชท และการระงับผู้ใช้งาน

### 2.2 ประเภทการทดสอบ (Testing Types)
* **Functional Testing:** ตรวจสอบความถูกต้องของฟังก์ชันและการไหลของกระบวนการตาม Requirements
* **Integration Testing:** ทดสอบการทำงานร่วมกันระหว่าง Frontend (React/Vite), Backend (Node.js/Express) และ Database (PostgreSQL/Supabase)
* **Performance & Load Testing:** ทดสอบการรองรับโหลดพร้อมกัน (Concurrent Users) และเวลาตอบสนอง (Response Time)
* **Security & Moderation Testing:** ทดสอบการป้องกัน JWT Token, Password Hashing, และระบบคัดกรองคำหยาบ/ความปลอดภัย
* **User Acceptance Testing (UAT):** ทดสอบการใช้งานจริงโดยกลุ่มตัวอย่างนิสิต/นักศึกษาและผู้ขับขี่

### 2.3 สิ่งที่ไม่ได้รับการทดสอบในรอบนี้ (Out of Scope)
* **Third-Party Payment Gateway แบบสด:** การตัดวงเงินผ่านบัตรเครดิต/เดบิตจริง (ในรอบนี้ใช้ระบบ Mock Payment และการตรวจสอบสลิปโอนเงิน)
* **Offline Operation:** การใช้งานขณะไม่มีสัญญาณอินเทอร์เน็ต (เนื่องจากระบบถูกออกแบบเป็น Cloud-based Realtime Application)
* **ระบบปฏิบัติการเวอร์ชันเก่าที่ไม่รองรับ:** เช่น Android ต่ำกว่าเวอร์ชัน 9, iOS ต่ำกว่าเวอร์ชัน 15

## 6. การประเมินความเสี่ยงและข้อจำกัด (Risks & Limitations)

### 6.1 ความเสี่ยงที่พบ (Identified Risks)
1. **ความเสี่ยงด้านสัญญาณอินเทอร์เน็ตระหว่างเดินทาง:** ผู้ใช้งานอาจอยู่ในพื้นที่สัญญาณไม่เสถียรระหว่างการนัดพบหรือการยืนยันขึ้นรถ
2. **ความเสี่ยงด้านปริมาณการใช้งานพุ่งสูง (Traffic Spikes):** ช่วงก่อนเริ่มและหลังจบงานอีเวนต์ขนาดใหญ่ (เช่น คอนเสิร์ต) อาจมีคำขอค้นหาทริปและการส่งข้อความแชทจำนวนมากพร้อมกัน
3. **ความเสี่ยงด้านความปลอดภัยและความประพฤติของผู้ร่วมเดินทาง:** การไม่ปฏิบัติตามข้อตกลง หรือปัญหาการสื่อสารระหว่างผู้ขับและผู้โดยสาร

### 6.2 แผนรับมือและบรรเทาความเสี่ยง (Mitigation Plan)
1. **จัดทีมซัพพอร์ตสแตนด์บายตลอด 24 ชั่วโมง:** มีทีมเทคนิคและ Customer Support คอยดูแลระบบและตอบข้อสงสัยของผู้ใช้ตลอด 24 ชม. ในสัปดาห์แรกของการเปิดใช้งานจริง (Go-Live Week)
2. **ระบบการดึงข้อมูลและเชื่อมต่ออัตโนมัติ (Auto-Retry & Polling):** ปรับปรุงให้หน้าแชทและสถานะการจองมีการดึงข้อมูลอัปเดตแบบอัตโนมัติเมื่อเครือข่ายกลับมาเชื่อมต่อ
3. **การตั้งค่า Auto-scaling และ Rate Limiting:** ใช้งาน Express Rate Limit เพื่อป้องกันการโจมตีหรือการยิง API ซ้ำซ้อน และใช้ความสามารถ Auto-scaling ของ Cloud Database
4. **ระบบรายงานและประเมินคะแนนพฤติกรรม (Moderation & Peer Rating):** สนับสนุนให้ผู้ใช้ตรวจสอบคะแนนดาวและข้อคิดเห็นก่อนตัดสินใจร่วมทริป พร้อมทั้งมีระบบแบนผู้ใช้ที่มีพฤติกรรมไม่เหมาะสม

> 1. ฟังก์ชันระดับวิกฤต (Critical / Blocker) มีอัตราการแก้ไขสำเร็จ 100%
> 2. อัตราความสำเร็จรวมของการทดสอบสูงถึง 96.0% ซึ่งผ่านเกณฑ์มาตรฐานการส่งมอบ
> 3. ข้อผิดพลาดระดับ High ที่ค้างอยู่ 1 รายการ (#BUG-102) มีมาตรการรับมือที่ชัดเจน และพร้อม Deploy ตัวแก้ไข Patch 1.1 ภายใน 48 ชั่วโมงหลัง Go-Live
